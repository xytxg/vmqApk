# 2.0 重构记录

基于 `2867df1`（v1.8.1）重构，保留 MIT 许可、应用 ID `com.vone.qrcode` 和服务名，兼容旧 `vone` 配置。

## 原问题与修改

- AGP 2.3.2、过期 JCenter/动态依赖 → AGP 8.9.2、Gradle 8.11.1、Google/Maven Central 固定依赖和 AndroidX。
- Activity 同时承担解析/签名/请求/配置 → 拆分 core、data、系统监听、UI 四部分。
- 无限线程、永久 WakeLock、反复创建客户端、回调线程 Looper.loop → 生命周期调度、共享客户端、20 秒总超时、主线程更新 UI。
- 未配置即发起非法 URL、手动和扫码重复代码、字符串引用比较 → 统一 ServerConfig 校验、验证成功再保存。
- 强制 HTTP → 兼容旧格式并支持 HTTPS、IPv6、端口和子目录；禁用请求重定向。
- 所有 HTTP 响应都视作成功 → 同时检查 HTTP 状态及 JSON code=1；限制读取响应大小。
- 取通知最后一个数字、直接 Double 解析 → 正则定位收款金额，BigDecimal 校验；发送时保留旧 Double 字符串格式，兼容服务端临时金额索引和签名。
- 收集全部应用通知日志和密钥明文展示 → 先按包过滤、只存运行结果、密钥遮蔽、禁用备份。
- 通知重发 → 持久化哈希去重；限制并发；失败明确提示人工核对，不自动重试非幂等入账。
- 自带过期摄像头/二维码实现、相册读取主线程、要求存储权限 → ZXing Embedded、系统图片选择器、后台限尺寸解码，无存储权限。
- 新系统通知权限、组件 exported 和边缘布局缺失 → target 35、通知权限流程、系统窗口 Insets、浅色/深色布局。
- 无 CI → GitHub Actions 单元测试、Lint、debug APK、release APK/AAB、校验和与构建说明。

## 验证范围

单元测试覆盖配置非法值、子目录/IPv6、金额昵称/尾部订单号/歧义/退款、旧签名规则、HTTP/业务失败和重定向。
构建验证结果以对应提交的 GitHub Actions 与测试/Lint报告为准。
没有用户服务端及微信/支付宝实机环境，未验证真实交易、厂商后台存活和各通知模板，详见 BUILD.md 限制。

## 后续建议

服务端提供可靠事件幂等键后，再增加离线队列和重试。增加真实设备/模拟器 UI 和通知生命周期测试，再扩展通知模板；不可将仅金额匹配视为支付渠道的官方认证结果。
